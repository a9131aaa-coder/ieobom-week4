입어봄 · PRD v1.1

AI와 창업혁신 5주차 · 2026-10-17 · 앱 버전 0.2.0

브랜드명은 4주차 가칭 ‘입어봄’을 유지합니다. **변경**과 **추가**가 v1 대비 변경사항입니다. 이 문서는 구현 범위와 확인 기준을 설명하며, API 키 등록·실제 AI 호출·공개 배포 완료를 대신 증명하지 않습니다.

이번 버전 한 문장

변경 예시 옷장과 취향을 서버에서 AI에 보내 코디 3개와 추천 이유를 받고, 대시보드에 표시합니다. AI가 실패하면 같은 모양의 예시 응답과 대체 안내를 보여줍니다.

1. 목적

가진 옷을 새롭게 조합해 출근·약속 준비를 돕습니다. 5주차의 핵심은 MOCK 입력 → 서버 API → 실제 AI → 검증 → 화면 표시입니다. 추천 품질·결제 의사는 아직 검증하지 않았습니다.

추가 사용자의 별도 요청에 따라 5개 메뉴를 모두 작동하도록 확장했습니다. 강의의 최소 범위보다 넓지만 DB와 로그인은 추가하지 않았습니다.

2. 사용자

단정함과 편안함을 선호하는 사회초년생을 초기 사용자로 가정합니다. 예시 프로필·의류·기존 기록은 가상이며 실제 고객 정보가 아닙니다. 가상 피팅, 사이즈 판정, 사진 분석은 제공하지 않습니다.

화이트·블랙, 얇은 선, 넓은 여백과 Pretendard를 유지합니다. 옷 그림은 분류를 보여주는 도식이며 실제 의류 사진이나 AI 분석 이미지가 아닙니다. 기존 기록의 이미지는 4주차 예시 썸네일입니다.

4. 데이터

추가 data/dashboard.json에 의류 12벌과 스타일 프로필 5개 항목을 추가했습니다. 기존 최근 기록 5건을 유지합니다. GET /api/dashboard는 서버 파일을 읽어 JSON을 제공합니다.

변경 화면의 옷 수·저장 기록 수·프로필 완성도는 브라우저 상태에서 계산합니다. v1의 17/20 상담 잔여량은 실제 할당량으로 오해하지 않도록 대시보드에서 제거했습니다. 이전 API 호환을 위해 summary의 예시 잔여량 값은 데이터에 남아 있습니다.

기본 분석은 서버의 MOCK 옷장·프로필을 사용합니다. ‘내가 수정한 옷장’을 선택하면 브라우저의 옷장·프로필을 서버에서 검증 후 AI로 보냅니다. 옷 이름 50자, 색 30자, 프로필 항목당 160자, 상황 40자, 추가 요청 300자, 요청 본문 20KB를 제한합니다. 최소 상의·하의·신발이 각각 1개 필요합니다.

추가 옷장·프로필·기록·최근 결과는 localStorage에 저장합니다. 폰과 PC는 같은 사이트를 열 수 있으나 개인 기록은 서로 동기화되지 않습니다. 저장 공간에 접근할 수 없으면 현재 화면에서만 동작하고 안내합니다. 로그인 계정, 클라우드 DB, 자동 취향 학습은 없습니다.

5. API와 기술 구성

  • Next.js App Router, TypeScript 라우트, 별도 CSS와 브라우저 JavaScript. 의존성 버전과 package-lock.json을 고정합니다.
  • GET /api/dashboard: MOCK 입력 데이터. 읽기 실패 시 500.
  • 추가 POST /api/suggest: 코디 분석 1개 API. AI 호출은 lib/ai.mjs의 suggestOutfits 함수 한 곳으로 모읍니다.
  • 변경 외부 데이터 API 0개 → Google Gemini API 1개. 서버 환경변수 LLM_API_KEY, LLM_MODEL만 사용합니다. 기본 모델 gemini-3.5-flash-lite는 2026-10-17 공식 문서에서 확인했습니다.
  • 키를 NEXT_PUBLIC_ 변수, URL, 브라우저 코드, 응답, 오류 로그에 넣지 않습니다. 공급자 오류 본문을 사용자에게 그대로 전달하지 않습니다.
  • .env.local은 Git에서 제외합니다. ZIP의 .env.example은 이름만 있는 빈 예시입니다. Vercel에는 별도로 환경변수를 등록한 뒤 재배포해야 합니다.

응답 형식:

{
  "summary": "분석 요약",
  "outfits": [
    {"title":"코디 이름","itemIds":["w01","w05","w10"],"reason":"이유","tip":"연출 팁"},
    {"title":"다른 코디","itemIds":["w02","w06","w11"],"reason":"이유","tip":"연출 팁"},
    {"title":"세 번째 코디","itemIds":["w03","w07","w10"],"reason":"이유","tip":"연출 팁"}
  ],
  "fallback": false,
  "reason": null,
  "model": "gemini-3.5-flash-lite",
  "usage": null,
  "generatedAt": "호출 시각",
  "source": "mock",
  "occasion": "출근"
}

위 JSON은 형식 설명용입니다. 실제 성공 증거가 아닙니다. usage에는 확인 가능한 공급자 토큰 수만 넣습니다.

6. 요청 흐름과 실패 대응

  1. 브라우저가 /api/dashboard에서 예시 데이터를 가져옵니다.
  2. 사용자가 ‘AI 코디 분석’을 누르면 POST /api/suggest를 호출합니다. 페이지를 여는 것만으로는 AI 비용이 발생하지 않습니다.
  3. 서버는 입력을 제한·검증하고 고정 지시문과 데이터를 분리해 Gemini에 보냅니다.
  4. JSON Schema 응답을 요청한 뒤 서버에서 다시 검사합니다. 코디가 정확히 3개인지, 텍스트 길이, 의류 ID가 실제 목록에 있는지, 상의·하의·신발 포함 여부를 확인합니다.
  5. 통과하면 fallback:false. 실패·키 누락·한도 초과·18초 시간 제한·빈 응답·불완전 응답·형식 오류는 fallback:true와 예시 3개를 반환합니다. 모두 AI 실패 상황에서는 HTTP 200입니다.
  6. 화면은 대체 결과에 ‘지금은 예시를 보여 드려요’를 표시합니다. 입력 오류는 400, 너무 큰 요청은 413, 잘못된 Content-Type은 415, 외부 Origin은 403, 기본 데이터 자체를 못 읽으면 503입니다. 이 경우에도 화면과 다른 메뉴는 유지됩니다.
  7. 마음에 드는 코디를 기록으로 저장하고 만족도를 남깁니다. 실제 AI 결과·예시 결과·초기 기록을 구분합니다.

예시 결과는 보유 목록으로 만드는 기본 조합이며, 요청 상황·취향을 실제 AI가 분석한 것처럼 표현하지 않습니다. 사용 가능한 의류가 적으면 예시 조합이 겹칠 수 있습니다.

추가 forceFallback:true는 AI를 호출하지 않는 수업용 실패 테스트입니다. 이 테스트 외에도 잘못된 키/모델·429·시간 초과·깨진 JSON을 자동 테스트합니다. 교수님이 실제 공급자 실패를 요구하면 Vercel에서 모델을 일시적으로 없는 이름으로 바꾸고 재배포해 확인한 후 복구합니다.

7. 제외 범위와 운영 한계

변경 ‘AI 분석 제외’, ‘나머지 메뉴 비활성’을 제거합니다. 로그인, DB, 사진 업로드·판독, 가상 피팅, 이미지 생성, 결제, 실제 날씨, 쇼핑몰, 스케줄, 자동 학습은 계속 제외합니다.

추가 서버 메모리에서 IP당 분당 5회, 인스턴스당 하루 100회를 제한합니다. 서버리스 인스턴스가 여러 개이거나 재시작되면 합산/보존되지 않는 교육용 제한입니다. 이는 계정별 크레딧이나 비용 상한이 아닙니다. 공급자의 실제 할당량·결제 설정은 별도로 관리합니다.

토큰 비용은 무료 티어의 실제 청구액이 아닌 유료 Standard 단가 환산치입니다. 기본 모델의 입력 $0.30/100만, 출력·추론 $2.50/100만, 수업 환율 1,350원을 사용합니다. 다른 모델이면 토큰 수만 표시하고 임의 단가로 계산하지 않습니다. 단가와 모델 가용성은 변경될 수 있습니다.

8. 완료 기준

  • Vercel 공개 URL을 휴대폰에서 열 수 있다.
  • GET /api/dashboard가 200이다.
  • 실제 키로 POST /api/suggest가 200, fallback:false와 코디 3개를 반환한다.
  • 실제 결과가 홈과 상담 화면 모두에 나타난다.
  • 실패 테스트가 fallback:true이며 예시 안내가 나온다.
  • Network/소스에 API 키가 없다.
  • 모든 메뉴를 누를 수 있고 옷 등록·프로필 저장·코디 저장·착용/평가가 동작한다.
  • 새로고침 후 같은 브라우저의 기록이 유지된다.
  • npm test와 npm run build가 성공한다.
  • 실제 호출의 토큰 기록 CSV, 실패 캡처, PRD 링크, 회고를 준비한다.

개발 환경 자동 테스트와 실제 배포 환경의 검증은 구분합니다. 실제 키·공개 배포·휴대폰 결과는 배포 후 확인합니다.
