# 검증 기록

실행일: 2026-10-16. 이 보고서는 실제 실행한 점검과 아직 실행하지 못한 점검을 구분한다.

## 통과한 점검

- Node.js 22.16.0의 `node --test`로 테스트 6개 통과.
- JSON 데이터 유효성, 다섯 개 기록과 고유 ID, 숫자 범위 확인.
- 진행률 계산(17/20=85%)과 0 한도 처리 확인.
- 고정 화면에 숫자 카드 3개, 테이블 1개, 비활성 메뉴 4개 확인.
- 예시 숫자·상담 제목이 화면 템플릿에 하드코딩되지 않음을 확인.
- `scripts/preview.mjs` 보조 서버를 띄워 HTTP GET `/api/dashboard` 상태 200 및 JSON 응답 확인.
- 위 보조 서버에서 mock JSON을 잠시 잘못된 형식으로 바꾸면 실제 HTTP 500 반환. 파일 원복 후 200 복귀 확인.
- TypeScript transpileModule로 TS/TSX 파일 4개 구문 진단 0개. 전체 Next.js 타입 검사와는 다름.
- Chromium에서 동일 화면·브라우저 코드의 데스크톱 1440px 및 모바일 390/360/320px 표시 테스트. 가로 넘침 없음.
- UI 테스트에서 API 응답의 값을 변경해 다시 불러오면 카드에 반영됨을 확인.
- UI 테스트에서 500 응답, 오류 안내, 수치 초기화, 재시도 복구 확인.
- 응답의 HTML처럼 보이는 문자열이 실행되지 않고 일반 텍스트로 표시됨을 확인.
- PRD PDF를 생성하고 각 페이지를 이미지로 렌더링해 검사.

## 점검 방법의 제한

- 제작 환경에서 외부 npm 레지스트리 다운로드가 불가능했다. 그래서 `npm install`과 Next.js 실제 `npm run build`, 전체 `tsc` 검사는 실행 완료하지 못했다.
- Chromium 환경에서도 웹 탐색이 제한되어, UI 테스트에는 보조 서버에서 받은 JSON을 주입했다. UI 테스트용 fetch 대체 코드는 배포 파일에 들어 있지 않다.
- 스크린샷은 위 방식으로 렌더링한 화면이며, Vercel 배포 화면이나 실제 Chrome Network 캡처가 아니다.
- Pretendard CDN에 접근할 수 없어 스크린샷은 시스템 한글 대체 글꼴로 렌더링했다. 실제 사이트는 CDN 성공 시 Pretendard를 사용한다.
- 실제 외부 Vercel 배포 URL은 아직 생성하지 않았다. 사용자 계정에서 빌드와 공개 접근을 검증해야 한다.

## 사용자 계정에서 마무리할 점검

1. npm 설치 또는 Vercel Import 후 Build Logs에서 빌드 성공 확인.
2. Production URL을 시크릿 창과 휴대폰에서 열기.
3. Network 탭에서 `/api/dashboard` 실제 200 응답 캡처.
4. `/PRD.html` 문서 링크 열기.
5. 최초 npm 설치로 생성된 lockfile 저장. 실제 배포 환경의 의존성 보안 점검.
