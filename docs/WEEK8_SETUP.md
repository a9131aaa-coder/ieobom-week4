# 입어봄 8주차: 코디 기록에 질문하기

이번 주에는 **이미 저장된 공통 예시 코디 20개를 찾아 근거와 함께 답하는 챗봇**을 만듭니다. 교수님 공지의 mock Data는 이 수업용 예시 기록을 뜻합니다. 가짜 AI 답변을 표시한다는 뜻은 아닙니다.

로그인과 사용자별 개인 데이터 권한은 다음 주 범위입니다. 새 벡터 표를 서버만 읽게 제한하는 기본 보호는 이번에 포함합니다.

## 무엇이 추가되나요?

1. 코디마다 검색용 숫자 묶음(임베딩)을 한 번 만들어 DB에 저장합니다.
2. 질문도 같은 방식으로 바꾸어 비슷한 코디를 최대 5개 찾습니다.
3. AI는 그 기록을 읽고 짧게 답합니다. 실제로 사용한 기록만 카드로 보여 줍니다.
4. 기록에 없는 질문은 “근거를 찾지 못했어요”, 연결 실패는 “근거를 가져오지 못했어요”로 구분합니다.

검색 대상은 `demo-profile`의 `ieobom_outfits`입니다. 저장됨·착용 완료·피드백 대기 상태 모두 포함합니다. 브라우저에만 추가한 개인 기록은 검색하지 않습니다. 기록 날짜가 있다는 이유만으로 실제 착용했다고 판단하지 않습니다. 질문마다 독립적으로 처리하며 이전 대화는 기억하지 않습니다.

## 1. Supabase에 검색 자료를 담을 표 준비

지금 쓰는 `ieobom` 프로젝트를 열고 **SQL Editor → 새 쿼리**로 들어갑니다.
`supabase/005_rag.sql` 전체를 붙여 넣고 **Run**을 누릅니다.

이 SQL은 검색용 `content_embeddings` 표, 벡터 확장, 인덱스와 `match_contents` 검색 함수를 추가합니다. 기존 옷·코디 20개를 덮어쓰지 않습니다. 이 단계 직후에는 검색용 표가 비어 있는 것이 정상입니다.

## 2. 기존 설정에 모델 이름 추가

Vercel의 기존 `ieobom-week4` 프로젝트 → **Settings → Environment Variables**에서 추가합니다.

| 이름 | 값 |
|---|---|
| `EMBEDDING_MODEL` | `gemini-embedding-2` |
| `CHAT_MODEL` | `gemini-3.5-flash-lite` |
| `RAG_MATCH_THRESHOLD` | `0.45` (선택, 초기값) |

기존 `LLM_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 사용합니다. 실제 키를 소스 파일이나 채팅에 넣지 않습니다. 모델 이름 두 개는 비밀키가 아닙니다. 환경변수 변경은 재배포 후 적용됩니다.

## 3. 코디 20개를 검색 가능한 자료로 만들기

임베딩 생성은 관리용 명령입니다. 공개 웹페이지에는 데이터 쓰기 버튼을 만들지 않았습니다. **Node.js 22**가 설치된 컴퓨터에서 프로젝트 폴더를 열어 실행합니다.

`.env.example`을 복사해 `.env.local`로 만들고, 본인 컴퓨터에서 기존 설정의 값을 입력합니다. 이 파일은 GitHub에 올리지 않습니다.

```text
npm ci
npm run embed:dry-run
npm run embed
npm run embed:verify
```

- `dry-run`: DB에서 대상 수와 변경 여부를 읽습니다. 임베딩 AI 호출과 저장을 하지 않습니다. 비용은 텍스트 길이로 계산한 대략적인 범위입니다.
- `embed`: 실제 Gemini 호출로 768차원 임베딩을 만들어 저장합니다. 각 성공 건을 바로 저장하므로 중단 후 다시 실행할 수 있습니다.
- `verify`: 실제 컬럼 조회와 검색 함수 호출로 누락·모델·차원·벡터 길이를 확인합니다. 임베딩 AI는 호출하지 않습니다.
- 같은 내용·모델·차원은 다음 실행에서 건너뜁니다. 실행 속도는 분당 85회 이하로 제한하지만 계정별 할당량은 별도입니다.

현재 예시 데이터가 그대로라면 **원본 20건 = 임베딩 20건, 누락 0, 모델 1종, 768차원, 벡터 길이 약 1**이어야 합니다. 코디 내용을 Supabase에서 바꾸면 `npm run embed`를 다시 실행합니다. 갱신 전에는 오래된 근거로 답하지 않고 오류 안내를 표시합니다.

## 4. 기존 사이트에 반영

업데이트한 프로젝트 파일을 기존 GitHub 저장소에 반영합니다. 연결된 Vercel 프로젝트의 재배포가 완료되면 기존 주소에 `/chat`을 붙여 들어갑니다.

```text
https://ieobom-week4.vercel.app/chat
```

전체 프로젝트 ZIP을 쓴다면 **압축을 푼 파일과 폴더**를 저장소에 반영합니다. ZIP 파일만 저장소에 올려서는 코드가 적용되지 않습니다. `.env.local`, `node_modules`, `.next`는 업로드하지 않습니다.

## 5. 실제 답변 확인

화면의 예시 질문과 별개로 다음 질문을 확인합니다. 이 문장들은 답변 프롬프트에 정답으로 넣지 않았습니다.

| 종류 | 질문 | 기대 결과 |
|---|---|---|
| 관련 1 | 온라인 미팅 때 카메라에 보이는 옷차림을 확인하는 코디 기록을 찾아줘. | `look-015`의 셔츠 깃·구김 팁을 근거로 답변 |
| 관련 2 | 기차로 이동할 때 편한 조합과 실내 온도 대비 팁이 있는 기록을 찾아줘. | `look-010` 기록을 근거로 답변 |
| 자료 없음 | 스키장에 갈 때 저장한 방수 재킷 코디가 있어? | 근거 없음, 카드 0개 |
| 무관 | 자바스크립트 배열을 정렬하는 코드를 알려줘. | 근거 없음, 카드 0개 |
| 경계 | 기차 여행 코디에서 입은 베이지 팬츠의 브랜드와 구매 가격은 얼마야? | 관련 코디가 검색돼도 브랜드·가격이 없어 거부, 카드 0개 |

명령으로 5개 질문의 응답·출처·시간·토큰·비용 추정치를 모을 수도 있습니다. 실행하면 질문 5개가 실제 API로 전송됩니다.

```text
npm run rag:check -- https://ieobom-week4.vercel.app
```

자동 출력의 `correctness`는 “직접 확인 필요”입니다. 응답 성공만으로 정답이라고 판단하지 않습니다. 출처 ID와 인용문 검사는 기록의 존재를 확인하지만, AI가 쓴 모든 문장의 사실성을 완전히 보장하지는 않습니다.

추가 확인:
- 빈 질문과 301자 질문: AI 호출 없이 입력 오류.
- 검색 결과 0건: 답변 생성 AI 호출 없음.
- `CHAT_MODEL=gemini-invalid-test`로 잠시 변경 후 재배포: `fallback: true`와 오류 안내, 다시 질문 가능. 확인 뒤 원래 모델로 복구하고 재배포.
- `supabase/006_check_rag.sql`: 원본/임베딩 정합성과 공개 역할 접근 제한 확인.

유사도 0.45는 초기값입니다. 유사도가 높아도 가격처럼 없는 정보는 답하지 않아야 합니다. 유사도는 정답 확률이 아닙니다.

## 비용과 로그

서버는 요청마다 단계별 시간, 토큰, 검색 수, 출처 수를 한 줄로 기록합니다. 질문 원문·코디 본문·키·벡터는 기록하지 않습니다. 각 서버 인스턴스에서 분당 5회/IP, 하루 100회 제한을 두지만 전체 배포의 과금 상한을 보장하지는 않습니다.

비용 계산은 2026-11-21 Google 공식 요금표의 유료 Standard 단가를 기준으로 합니다. Embedding 2 텍스트 입력 $0.20/백만 토큰, Gemini 3.5 Flash-Lite 입력 $0.30·출력(생각 토큰 포함) $2.50/백만 토큰입니다. 환율은 1달러=1,350원이라는 **계산용 가정**이며 실제 청구액이 아닙니다. 사용량이 없거나 다른 모델이면 추정치를 만들지 않습니다.

## 교수님 참고 자료 활용

교수님이 공유한 StitchStyle ZIP은 HTML 5개·스크린샷 4개·디자인 명세 1개로 구성된 화면 참고 자료입니다. ZIP 안에는 실제 AI/API/DB 연결 코드가 없습니다. 배포 사이트의 실제 사진 분석 기능은 별도로 검증하지 않았습니다.

입어봄에는 목적이 분명한 제목·질문 예시·이미지와 설명을 묶은 근거 카드 구성을 참고했습니다. 체형·퍼스널컬러 분석이나 사진 업로드는 이번 기록 검색 범위에 추가하지 않았습니다. ZIP의 타이머 기반 예시 분석 결과도 가져오지 않았습니다.

## 개발 검증

```text
npm test

```

코드 테스트는 외부 API를 대체해 실패 처리와 계약을 검사합니다. 실제 임베딩 생성, DB 권한, 검색 품질, 배포 화면은 위 설정 후 별도로 확인해야 합니다.

참고: [Gemini 임베딩 공식 문서](https://ai.google.dev/gemini-api/docs/embeddings), [요금표](https://ai.google.dev/gemini-api/docs/pricing), [Supabase 벡터 컬럼](https://supabase.com/docs/guides/ai/vector-columns).
Embedding 2는 최신 공식 API에 맞춰 문서/질문 접두사를 사용합니다. 강의의 문서와 질문 역할 구분은 유지하며, 구형 모델용 `taskType` 설정은 보내지 않습니다.
